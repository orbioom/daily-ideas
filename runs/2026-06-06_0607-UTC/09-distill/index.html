PPM (Prediction by Partial Matching). Distill reads your bytes one at a time and, for each one, asks: given the previous up-to-three bytes (the context), how likely is each possible next byte? It keeps frequency counts per context. Natural language is deeply predictable — after q comes u, after th comes e — so these predictions get sharp, and sharp predictions cost few bits.

Escape & exclusion (PPMC). When the model has never seen the next byte in the current context, it emits a small escape and falls back to a shorter context, and ultimately to a uniform model over all 256 byte values plus an end-of-stream marker. Symbols already ruled out higher up are excluded from the lower-order estimates, which tightens the probabilities. This fallback chain is what guarantees every possible input is codable — and that the coder is exactly lossless.

Range coding. Those probabilities drive a 32-bit carry-less range coder, the arithmetic-coding family that turns a stream of probabilities into a near-optimal stream of bits. It is deterministic: the same input always produces the same bytes.

The gzip comparison is honest. The gzip figure is produced by your browser's own built-in CompressionStream('gzip') — no fabricated numbers. Everything you see is computed live on your actual input. On natural-language prose Distill typically beats gzip's ratio because it models longer context than gzip's LZ77 + Huffman pipeline; on tiny or already-dense/random data, gzip's lighter header often wins, and Distill says so plainly.

Verified lossless. After compressing, Distill immediately decompresses its own output inside the worker and checks it byte-for-byte against your input. The green check only appears when that check passes.

Engine: order-3 PPMC + carry-less range coder · runs in a Web Worker · inputs capped at 512 KB for a responsive demo · no network, no keys, no CDN.
