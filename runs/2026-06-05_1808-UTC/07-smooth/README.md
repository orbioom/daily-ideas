# Smooth — Savitzky–Golay Signal Smoothing & Differentiation

An interactive, browser-based workbench for applying the Savitzky–Golay filter to 1-D signals, with live controls for window length, polynomial order, and derivative order.

---

## The science for a smart non-expert

A **moving average** replaces each sample with the arithmetic mean of its neighbours. It smooths noise but also smears sharp peaks — because it weights every neighbour equally, it cannot distinguish a true peak from a noisy excursion.

**Savitzky–Golay (SG) smoothing** fixes this by fitting a low-degree polynomial (quadratic, cubic, etc.) to each window of neighbouring points using ordinary least squares, then evaluating the polynomial at the centre point. Because a polynomial can follow curvature, it tracks peaks and troughs far more faithfully than a simple average — it's mathematically equivalent to convolving the signal with a set of coefficients derived from the polynomial fit, which is why it can be computed as efficiently as a moving average once those coefficients are known.

**Key jargon:**
- **Window length (2m+1):** How many neighbouring samples are included in each local fit. Longer → more smoothing, but may blur fine features.
- **Polynomial order (p):** The degree of the polynomial. Higher → captures more curvature; requires a wider window to remain well-determined (window ≥ p+2).
- **Convolution coefficients:** The fixed weights applied to the windowed data. For a centred window they are symmetric; computed once from the design matrix, not tabulated.
- **Derivative order (d):** Instead of evaluating the polynomial value, evaluate its d-th derivative — this gives a smoothed numerical derivative essentially for free.

## Method & Citations

### Primary reference

> Savitzky, A.; Golay, M.J.E.  
> "Smoothing and Differentiation of Data by Simplified Least Squares Procedures."  
> *Analytical Chemistry*, **1964**, *36*(8), pp. 1627–1639.  
> DOI: [10.1021/ac60214a047](https://doi.org/10.1021/ac60214a047)

### Exact algorithm (as implemented in `js/savgol.js`)

For a window of `2m+1` points indexed `j = 0…2m` with coordinates `xⱼ = j − m`:

1. **Design matrix** A (size (2m+1) × (p+1)): `A[j, k] = xⱼᵏ`
2. **Normal equations**: `(AᵀA) v = e_{x₀}`, where `e_{x₀}` is the evaluation vector:
   - Smoothing (d=0): `e[k] = x₀ᵏ`
   - d-th derivative: `e[k] = (k!/(k−d)!) · x₀^(k−d)` for k ≥ d, else 0
3. **Solve** the (p+1)×(p+1) system by Gaussian elimination with partial pivoting (coded from scratch — no external linear-algebra library).
4. **Convolution weights**: `w = A · v` (length 2m+1)
5. **Apply**: result[i] = dot(w, signal[winStart … winStart+2m])

### Edge policy

**Asymmetric SG coefficients** (Savitzky & Golay 1964, Appendix). For the first `m` and last `m` points, the full window of size `2m+1` is anchored at the signal boundary, and the polynomial is evaluated at the offset `x₀ = i − m` (left boundary) or `x₀ = i − (n − 2m − 1) − m` (right boundary). This is exact — the same polynomial model, just with the evaluation point shifted off-centre — not zero-padding, not truncation.

### Honest simplifications

- Samples are assumed **uniformly spaced** (Δx = 1 sample index). Derivative values are therefore in `[signal unit / sample]`. For physical derivatives, divide by the physical Δx.
- The implementation uses **float64** arithmetic throughout; numerical errors are on the order of 10⁻¹² for reasonable window/order combinations.

## Data

### Synthetic signals (seeded, reproducible)

All synthetic data uses a seeded LCG (Linear Congruential Generator) with parameters from *Numerical Recipes* (Press et al.):

```
s ← (1664525 · s + 1013904223) mod 2³²
uniform ← s / 2³²
```

Gaussian noise is produced via the Box-Muller transform. Every page load produces **identical data** because the seeds are fixed constants.

| Signal | Seed | Description |
|---|---|---|
| Gaussian Peak + Baseline | 0xDEADBEEF | 4·exp(−½t²) + 0.3·i/N + 0.5 + noise σ≈0.15 |
| Multi-Peak Spectrum | 0xCAFEBABE | 4 overlapping Gaussian peaks + noise σ≈0.18 |
| Noisy Sine Wave | 0x13579BDF | sin(2π·4·t) + 0.5·sin(2π·13·t) + noise σ≈0.4 |
| Step Function + Noise | 0x2468ACE0 | 3-level step function + noise σ≈0.12 |

### sample.csv

`data/sample.csv` contains 256 points of the "Gaussian Peak + Baseline" synthetic signal generated by the same seeded algorithm (Python script matching the JavaScript LCG exactly), committed as a reference dataset. Header: `x,y` (sample index, signal value; arb. units).

## Controls & Export

| Control | Description |
|---|---|
| Data Source | Select one of 4 synthetic signals, or switch to custom paste |
| Window Length | Odd integer ≥ poly.order+2; slider (3–101) or number input (up to 999) |
| Polynomial Order | 1–5; higher tracks curvature better, needs wider window |
| Derivative Order | 0 (smoothed value), 1 (1st derivative), 2 (2nd derivative) |
| Paste Custom Data | Newline/comma-separated numbers; Ctrl+Enter or "Load" button |
| ↓ PNG | Exports the chart as a PNG image (Blob download) |
| ↓ CSV | Exports x, raw, smoothed, derivative as CSV (Blob download) |
| Sanity checks | Re-run mathematical invariant checks in the browser; results shown inline |
