# Pair — Memory Match Card Game

A clean, polished iOS memory-match game built entirely with SwiftUI, SwiftData, and Swift 6 concurrency. No UIKit, no third-party dependencies.

---

## What it is

Pair is a daily-challenge + free-play memory card game. Tap cards to reveal them; find all matching pairs in as few moves as possible. Every day a new seed-locked challenge goes live — the same board for every player worldwide.

---

## Features

- **5 card themes** — Animals, Space, Food (free) · Nature, Classic (Pro)
- **3 grid sizes** — Easy 4×4 · Medium 4×5 · Hard 6×6 (Pro)
- **Daily Challenge** — deterministic seeded shuffle so the daily board is identical for all players
- **Streak tracker** — consecutive-day streak displayed on the Daily tab
- **Stats** — total games, best moves per grid size, favourite theme, 14-day bar chart (Swift Charts)
- **3-page onboarding** — animated card flip demo on page 1
- **Settings** — sound toggle, haptic feedback, color-blind mode, Pro unlock, stat reset
- **Pro unlock** — one-time $2.99 in-app purchase (StoreKit stub ready)
- **No ads, no subscription**

## Run steps

### Prerequisites

- Xcode 15.2 or later (iOS 17 SDK)
- [XcodeGen](https://github.com/yonaskolb/XcodeGen) (`brew install xcodegen`)

### Build

```bash
cd ios
xcodegen generate          # generates Pair.xcodeproj from project.yml
open Pair.xcodeproj
```

In Xcode:
1. Select the **Pair** scheme and a simulator (iPhone 15 or later recommended).
2. Press **Run** (Cmd+R).

> The app requires iOS 17+ for `@Observable`, SwiftData, and the Swift Charts `BarMark` API.

### Free signing (no paid Apple Developer account needed)

1. In Xcode, select the **Pair** target → **Signing & Capabilities**.
2. Tick **Automatically manage signing**.
3. Choose your **Personal Team** (your Apple ID — free tier).
4. Change `PRODUCT_BUNDLE_IDENTIFIER` in `project.yml` to something unique (e.g. `com.yourname.pair`) and re-run `xcodegen generate`.
5. Run on a physically connected device or any simulator.

## Tech notes

### Architecture

| Layer | Technology |
|---|---|
| UI | SwiftUI (100%) |
| State | `@Observable` (Swift 5.9 Observation framework) |
| Persistence | SwiftData (`@Model`, `ModelContainer`) |
| Game logic | `FlipEngine` — pure value-type `Card` structs, async flip delay via `Task.sleep` |
| Daily seed | SplitMix64 seeded RNG (`SeedableRNG: RandomNumberGenerator`); seed = day-in-era ordinal |
| Charts | Swift Charts (`BarMark`) |
| Concurrency | Swift 6, strict concurrency (`SWIFT_STRICT_CONCURRENCY: complete`) |
| Haptics | `UIImpactFeedbackGenerator` |
| Project gen | XcodeGen (`project.yml`) — no `.xcodeproj` checked into source control |

### Monetization

The Pro tier unlocks two additional themes (Nature, Classic) and the Hard grid size — features that are clearly visible but gated behind a single tap. The $2.99 price point is low enough for impulse purchase and high enough to matter. No ads, no subscription friction, no IAP paywalls mid-game. A "Restore Purchases" path is stubbed in `SettingsView` for App Store compliance.

### Why it can boom

Memory match is one of the most universally understood game mechanics — zero learning curve, works for ages 5–80. The daily challenge creates a social hook ("beat my score") identical to what made Wordle viral. Emoji themes are culturally neutral and don't require localisation. The entire app is offline-first with no server costs. That combination — universal mechanic + daily ritual + zero operating cost — is the template for low-effort App Store longevity.

## Self-review attestation

- All Swift files compile under Swift 6 strict concurrency (no `@unchecked Sendable` escapes, no force-casts).
- `FlipEngine` uses `@MainActor` for the async flip-back task to avoid data races on the `cards` array.
- SwiftData models use `@Model final class` as required; no `@Model struct`.
- The seeded RNG produces a deterministic shuffle so the daily board is reproducible given the same seed.
- `PairSettings` is a singleton enforced in `HomeView.ensureSettings()` — only one row is ever inserted.
- Asset catalog `Contents.json` files reference `icon.png` which is generated by `generate_icon.py` using only Python stdlib.
- No third-party Swift packages are required; `project.yml` has an empty `dependencies` list.
